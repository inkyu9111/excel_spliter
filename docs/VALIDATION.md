# 실행 검증

2026-10-05, Windows의 실제 데스크톱 Excel에서 합성 `.xlsx`로 확인했다. 회사 자료나 DRM 문서는 사용하지 않았다. 현재 지원 범위는 [README](../README.md), 보존 계약과 처리 구조는 [설계 문서](DESIGN.md)를 따른다.

## 환경과 재현

- Excel File Toolkit 0.3.0. 저장소 기준 커밋 `0b50ba7`, 작업 브랜치 `improve/reliable-merge-and-ui`.
- Windows 11, 한국어 Excel 16.0 build 20430.0, Python 3.12.14 64비트.
- pywin32 312, pytest 8.4.2, PyInstaller 6.22.2. 런타임 의존성 추가 없음.
- 로그와 JUnit 결과는 로컬 `build/`에 보관하며 Git에는 포함하지 않는다.

저장소 루트에서 실행한다. COM·Tk·파일 잠금 검사는 로그인한 Windows 데스크톱 세션을 사용한다. Excel E2E는 클립보드를 공유하므로 순차 실행한다.

```powershell
.\.venv\Scripts\python.exe -m pytest tests/unit -q -rs --junitxml=build/fast-final.xml
$env:EXCEL_E2E = "1"
.\.venv\Scripts\python.exe -m pytest tests/e2e -q -s --junitxml=build/native-final.xml
Remove-Item Env:EXCEL_E2E
.\scripts\build.ps1 -SkipTests
```

`-SkipTests`는 동일 소스의 회귀 검사를 이미 통과한 경우에만 사용한다. 샌드박스에서 COM·임시 폴더·하드 링크 접근이 막힌 실행은 정상 데스크톱 실행과 구분한다. 권한 때문에 건너뛴 검사는 통과로 세지 않는다.

실제 Excel E2E는 다섯 흐름을 한 번에 순차 실행해 **5 passed, 432.40초**로 마쳤다. 검사용 Table의 경계와 시트 순서도 저장 후 다시 열어 확인한다. 시간은 자료 생성·결과 재열기·기대값 검증을 포함하며 앱의 처리 시간만을 뜻하지 않는다.

배포 파일은 `dist/ExcelFileToolkit.exe` 하나다. 패키징한 EXE의 시작·종료를 확인했고, 전체 데이터 E2E는 같은 소스를 Python으로 실행했다.

- 크기: 14,730,383바이트
- SHA-256: `f0d71fc258983c3f9d792f340a7094c052da703371cba995d31c62631882c668`

## 검증 범위

| 실행 | 독립적으로 확인하는 결과 |
| --- | --- |
| Merge | 저장 후 모든 셀의 값·순서·자료형, 중복, 계산값, Excel 오류, 표시 형식, 합계, 첫 입력과 후속 입력의 필터·숨김 행, 빈 Table·단일 셀, 같은 파일명, 조건부 서식 |
| Split → Merge | 고정 기대값과 행별 중복 횟수, 한글·공백 경로, 빈 분류, 활성 Table 필터, 수식·스타일, 오래된 검사·경로 충돌 거부, 출력 잠금·덮어쓰기·부분 성공, 원본 서명과 임시 파일 정리. 사업소 15개 역순·중복 입력의 고정 접두사와 저장한 모든 행, 누락·추가·공백·빈 셀·오류 값의 옵션 거부 |
| Compare | 위치·복합 키, 재정렬, 추가·누락, 타입, 색칠, 비교대상 수식·서식과 모든 원본 보존 |
| Etc | 6개 정리 옵션 조합, 선택 시트·여러 Table 머리글, 도형·댓글·채우기·조건부 서식, 다른 시트와 원본 보존 |
| GUI → Excel | 실제 Tk 파일 선택·시트·열·폴더·패턴, 시작 버튼 한 번으로 병합·분할 저장, 검사 오류 후 재시도, 실행 중 입력 잠금, 결과에서 비교 화면으로 이동, 새 병합 결과 확인창 0회. 사업소 체크박스 활성·무효화·다시 선택·01~15 파일 저장·모든 행 대조 |

병합 검사는 합성 원본을 만든 뒤 결과를 Excel에서 다시 열어 고정 기대값과 비교한다. 서비스를 호출하는 테스트와 별도로 실제 Tk 컨트롤·작업 큐·컨트롤러·Excel을 연결한 E2E를 실행한다. GUI E2E에서 파일 선택·확인 대화상자만 자동 응답하며 서비스나 Excel을 대체하지 않는다.

반복 세션 검사는 메인 스레드 6회 → 작업 스레드 6회 → 메인 스레드 2회와 저장하지 않은 통합문서의 예외 3회를 포함한다. 호출자 변수와 예외 traceback을 유지한 상태에서도 세션 종료 시 모든 자식 COM 포인터가 해제되는지 확인한다.

빠른 테스트는 파일 게시 중 경합, 저장 결과 손상, COM 실패, command 스레드 시작·종료 실패, GUI 오류 복구 등 결정적으로 재현해야 하는 경계를 유지한다. 접두사 자격은 같은 크기·수정 시각의 원본 바이트 변경, 선택·사전 검사·실행 실패에서도 확인한다. 생성자·단순 전달만 확인하던 중복 테스트는 제거했다.

## 성능

조건부 서식 지원 여부 검사만 비교했다. 기준 모듈은 `0b50ba7`의 `merge_conditional_formats.py`이며 각 경우를 5회 교차 측정했다. 20,000행 × 8열의 합성 ZIP에서 고정 기대 판정과 원본 바이트 보존도 확인했다.

| 입력 | 기준 중앙값 | 현재 중앙값 |
| --- | ---: | ---: |
| 조건부 서식 없음 | 0.0095초 | 0.0098초 |
| 조건부 서식 있음 | 2.3154초 | 0.0144초 |

조건부 서식이 있는 경우 셀 데이터를 XML DOM으로 만들지 않아 검사 시간이 약 160배 줄었다. ZIP 내부 읽기는 5회로 동일하다. 이 수치를 전체 병합 속도 향상으로 해석하지 않는다. 원본 값 대조와 결과 재열기는 데이터 보존을 위해 수행한다.

```powershell
.\.venv\Scripts\python.exe scripts/benchmark_merge_cf.py --baseline build/cf-baseline.py
```

baseline 인수에는 비교할 기준 커밋에서 추출한 모듈 파일을 전달한다. 실제 Excel에서 두 파일의 26,000행 × 8열을 병합한 결과 사전 검사 **2.427초**, 저장·결과 재열기·값 대조를 포함한 실행 **12.372초**였다. 100,000셀 전송 경계를 넘는 데이터도 모두 대조했다. 이 전체 병합 사례의 이전 버전 비교값은 없다. 시간은 PC 부하에 따라 달라지므로 고정 시간 제한을 성능 통과 기준으로 사용하지 않는다.

분류 열 선택 때 읽은 스냅샷은 원본 SHA-256이 같으면 시작 시 재사용한다. 열 선택과 접두사 사전 검사에서 열 조회가 한 번인지, 실행 후 폐기하고 같은 크기·수정 시각의 내용 변경도 다시 읽는지 회귀 검사로 확인했다. 실제 Excel의 15개 접두사 분할과 재열기·전체 행·원본 보존 검증은 26.72초였다.

## 검증의 한계

- 현재 Windows 계정에 심볼릭 링크 생성 권한이 없어 관련 4건은 skip이다. 하드 링크와 일반 경로 보호 검사는 별도로 실행했다.
- 실제 Tk의 900×600 창에서 네 작업의 설정·저장·실행 컨트롤 경계, Canvas 없음, 긴 경로, 200개 키·1,000개 결과의 내부 스크롤과 결과→설정 복귀를 검사했다. Windows 화면 캡처로 현재 데스크톱 배율의 네 화면을 직접 확인했으며 모든 배율·해상도를 확인한 것은 아니다.
- 회사 DRM·보안 프로그램, 다른 Excel 버전, 네트워크 공유·동기화 폴더, 행 한도 근처의 장시간 작업은 이 검증에 포함하지 않았다.
- 강제 종료·전원 차단, 다른 앱의 클립보드 간섭, 모든 서식의 완전한 동일성을 보장하지 않는다. 값 검증 실패 결과는 게시하지 않는다.
- 분할 시 다른 시트 참조가 `#REF!`가 되는 지원 한계를 실제 확인했다. 분할은 선택 시트와 해당 분류 행을 남기며 참조 복구는 제공하지 않는다.
