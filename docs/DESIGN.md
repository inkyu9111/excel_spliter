# Excel File Toolkit 설계

Excel File Toolkit은 Windows의 데스크톱 Excel을 이용해 `.xlsx` 파일을 분할·병합·비교하고 시트를 정리한다. Python 3.12, 표준 Tkinter/ttk, pywin32를 사용하며 PyInstaller로 배포한다. 실제 통합문서의 읽기·편집·저장은 Excel이 수행한다.

사용 방법과 실행 명령은 [README](../README.md), 실행한 검증의 결과와 한계는 [검증 기록](VALIDATION.md)에 둔다. 이 문서는 현재 코드의 구성과 데이터 보존 계약을 설명한다.

## 공통 보존 계약

- 원본 파일에 저장하지 않는다. 원본은 읽기 전용으로 열거나 복사한 뒤 작업하며 크기·수정 시각·SHA-256으로 변경을 검사한다.
- 결과는 대상 폴더의 임시 `.xlsx`에 먼저 저장하고 검증한 뒤 최종 경로에 게시한다. 실패한 임시 결과를 완료 파일로 표시하지 않는다.
- 새 경로에는 기존 파일을 덮지 않는 Windows rename을 사용한다. 분할·병합에서 승인받은 기존 결과는 복구 경로로 옮긴 뒤 서명을 재확인하고 교체한다. 제3자가 최종 경로를 점유했으면 덮어쓰지 않으며 복구 파일 경로를 알린다.
- 비교와 시트 정리는 항상 새 결과 경로를 요구한다. 모든 작업에서 원본과 같은 파일을 결과로 지정할 수 없다.
- 입력 형식은 `.xlsx`이며 Excel용 절대 경로는 임시 경로까지 218자 이내여야 한다. 경로의 대괄호, Windows 예약 이름, 지원하지 않는 확장자 등을 사전에 검사한다.
- 외부 링크를 갱신하거나 매크로·이벤트를 실행하지 않도록 작업용 Excel을 설정한다. 파일 암호를 입력받거나 조직의 DRM 정책을 우회하는 기능은 제공하지 않는다.
- 열기·저장·닫기·게시 오류는 성공으로 처리하지 않는다. 오류가 발생한 단계, 관련 파일, 원래 예외와 COM 오류 정보를 진단에 남긴다.

분할의 원자성은 파일 단위다. 일부 결과가 완성된 뒤 다른 분류가 실패하면 완성된 파일을 유지하고 성공·실패·미시작 항목을 구분한다. 임시 파일 정리에 실패하면 처리 오류와 잔존 경로를 함께 알린다.

## 화면과 작업 수명

화면은 **파일 분할 / 파일 병합 / 파일 비교 / 시트 정리** 네 작업으로 구성한다. 각 화면은 입력 파일, 작업 설정, 저장 위치 순서로 배치하고 작업 버튼과 진행 상태는 하단에 고정한다. 좁은 창에서는 설정 영역을 스크롤한다. 실행할 수 없는 이유, 전체 경로, 예상 결과를 화면 안에서 확인할 수 있다.

병합은 파일 추가·다중 선택 제거·위아래 순서 이동을 제공한다. 첫 파일이 결과 서식의 기준이며 파일 순서가 데이터 순서다. 분할·병합은 시작 버튼 한 번으로 사전 검사와 실행을 이어가며 별도 사전 검사 버튼을 제공하지 않는다. 기존 파일 덮어쓰기와 분할의 삭제 범위만 필요한 시점에 확인한다. 내부 사전 검사에서 원본과 결과의 서명을 고정하고 실행 시 다시 대조한다.

서비스 호출은 백그라운드 작업에서 수행하고 Tk 위젯은 메인 스레드에서만 갱신한다. 실행 중에는 입력과 중복 실행을 막는다. 완료량을 아는 단계는 처리 개수를, 모르는 단계는 단계명과 경과 시간을 표시한다. 오류 뒤에도 원인·상세·로그 접근과 다음 작업의 진입 경로를 남긴다.

완료 패널은 결과 파일·폴더 열기와 선택 결과 확인을 제공한다. 병합 결과를 비교 대상으로 넘길 수 있다. 비교 내역은 최대 1,000건을 화면에 보관하며 전체 건수와 생략 건수를 따로 표시한다. 이 표시 한도는 실제 비교나 색칠 범위를 제한하지 않는다.

## 구성과 Excel 소유권

| 영역 | 주요 모듈 | 책임 |
| --- | --- | --- |
| 앱과 화면 | `app`, `toolkit_gui`, `gui`, `controller`, `ui_helpers` | 서비스 조립, 입력 상태, 작업 이벤트, 결과·오류 표시 |
| 분할 | `split_service`, `source_session`, `excel_gateway`, `parallel_writer` | 원본 세션, 분류 스냅샷, master 생성, 병렬 결과 작성 |
| 값과 파일명 | `models`, `classifier`, `snapshot_reader`, `naming`, `file_signature` | COM과 분리된 값, 분류, 경로, 변경 감지 |
| 병합 | `merge_service`, `merge_conditional_formats` | 입력 검사, 값·서식 병합, 저장 결과 대조, 조건부 서식 복원 |
| 비교·정리 | `compare_service`, `etc_service`, `excel_artifacts` | 차이 표시와 선택 시트 정리 |

`_excel_session`은 현재 작업 스레드에서 COM을 초기화하고 `CoCreateInstanceEx`로 별도 Excel 인스턴스를 만든다. 사용자가 열어 둔 Excel을 조회하거나 전역 프로세스 종료를 하지 않는다. 종료 시 숨은 저장 질문이 뜨지 않도록 경고를 끈 상태로 Quit을 호출한다. 세션에서 생성한 통합문서·시트·범위의 dispatch와 지연 type-info까지 같은 스레드에서 해제한 뒤 COM을 종료한다. 호출자 변수나 예외 traceback이 남아 있어도 COM 참조는 유지하지 않으며 COM 객체를 스레드 밖으로 전달하지 않는다. 이는 [COM 종료 전 인터페이스를 해제해야 하는 수명 규칙](https://devblogs.microsoft.com/oldnewthing/20200129-00/?p=103380)을 따른다.

분할의 `SourceSession`은 전용 command 스레드와 큐를 통해 원본을 재사용한다. 처음 파일을 선택할 때 파일 서명을 구하고 통합문서를 열며, 이후 시트·열 조회와 사전 검사는 같은 통합문서를 사용한다. 가벼운 조회는 크기·수정 시각으로 확인하고 실제 저장 직전에는 전체 서명을 다시 검사한다. 사전 시작 실패는 다음 작업에서 재시도할 수 있으며 작업 스레드가 종료되면 대기 중인 요청에도 실패를 전달한다.

병합·비교·정리는 작업별 Excel 세션을 사용한다. GUI의 사전 검사와 실행이 다른 스레드에서 실행되어도 서비스에 COM 객체가 남지 않아야 한다. 자동 검증에는 같은 스레드에서 세션을 여러 번 시작·종료하는 경우와 GUI처럼 작업마다 새 스레드를 사용하는 경우를 모두 포함한다.

## 파일 분할

선택한 표시 워크시트에 일반 범위 기반 Table(`ListObject`, `xlSrcRange`)이 정확히 하나 있고 데이터 행이 있어야 한다. 보호된 시트·통합문서, 외부 연결 Table, 행 삭제로 영향을 받는 Table 아래 독립 콘텐츠는 거부한다.

분류 열의 `Value2`를 한 번 읽고, 각 분류의 첫 셀에서만 표시 문자열 `Text`를 조회한다. 분류와 원본의 1-based `ListRow` 인덱스를 사전 검사에 고정하므로 다른 시트나 행을 삭제한 뒤 수식 값이 변해도 소속을 재판정하지 않는다.

| 값 | 분류 규칙 |
| --- | --- |
| 빈 셀·수식 결과 빈 문자열 | 같은 빈 분류 |
| 논리값 | 숫자와 구별 |
| 숫자·날짜 직렬값 | 수치로 비교, `1`과 `1.0`은 같음 |
| 텍스트 | 대소문자·앞뒤 공백을 유지 |
| Excel 오류 | 오류 코드별로 구별 |

분류는 처음 나타난 순서대로 표시한다. 파일명 패턴의 모든 `%`를 대표 문자열로 바꾸며 빈 분류는 빈 문자열로 치환한다. 금지 문자는 `_`로 바꾸고 예약 이름에는 `_` 접두사를 붙인다. 정리된 이름끼리 겹치면 ` (2)`, ` (3)`을 붙인다.

실행 시 원본을 Excel에서 출력 폴더의 작업 전용 `m.xlsx`로 SaveAs한다. 열린 통합문서의 경로가 master인지 확인한 다음 활성 필터를 해제하고 메모·댓글·도형을 한 번 정리한다. 일반 XLSX 패키지와 Table 구조를 검사하고 다시 열 수 있는지 확인한 뒤 출력 작업을 시작한다. Excel에서 열 수 있는 DRM 입력도 이 일반 파일 생성 기준을 만족해야 한다.

출력 worker는 최대 세 개이며 각각 별도 Excel과 임시 복사본을 소유한다. 제외 행은 연속 블록으로 묶어 높은 인덱스부터 삭제한다. 지원되지 않는 블록 삭제나 Excel 1004가 발생하면 해당 임시 복사본을 폐기하고 새 master 복사본에서 행별 삭제를 한 번 시도한다. 수동 계산을 사용할 수 있으면 편집을 병렬화하되 계산·설정 복원·저장은 직렬화한다. 호환성 문제가 있으면 편집부터 저장까지 직렬 처리한다.

결과는 선택 시트만 남기며 해당 분류의 행을 원본 순서대로 유지한다. Table 서식·합계·계산 열과 남은 셀의 수식·서식은 Excel이 행 삭제에 맞게 조정한다. 숨겨진 행과 필터에서 제외된 행도 분류에 포함한다. 메모·댓글과 `Shapes` 컬렉션의 그림·차트·버튼은 삭제하며 실행 전에 알린다. 삭제한 다른 시트를 참조하는 수식 등은 `#REF!`가 될 수 있으므로 실행 전에 별도 안내한다.

## 파일 병합

입력은 두 개 이상이며 각 파일에는 표시 워크시트 하나와 일반 Table 하나가 있어야 한다. 열 이름과 순서, 날짜 체계(1900/1904)가 같아야 한다. 빈 Table은 허용한다. 첫 파일의 Table 위치·스타일·합계 행과 Table 밖 내용을 기준으로 삼으며, 확장 범위에 값·수식·병합 셀·하이퍼링크·메모가 있으면 덮어쓰지 않는다. 서식만 있는 빈 셀은 확장할 수 있다.

파일별 데이터 행을 목록 순서대로 이어 붙인다. 중복 행을 제거하거나 원래의 교차 순서를 재구성하지 않는다. 필터·숨김 여부와 관계없이 모든 Table 데이터 행을 포함한다. 원본의 계산 결과를 값으로 붙여 넣으며 숫자 형식과 서식을 함께 옮긴다. 결과의 데이터 영역에는 수식을 남기지 않고 첫 파일의 합계 행은 유지한다.

병합은 다음 순서로 결과를 확인한다.

1. 사전 검사의 원본·기존 결과 서명을 다시 확인하고 첫 파일의 임시 복사본을 만든다.
2. 원본을 계산한 뒤 최대 100,000셀 단위로 값의 지문을 기록하고 서식과 값을 붙여 넣는다.
3. 행 수와 수식 잔존 여부를 검사하고 결과를 저장한다.
4. 적용 가능한 전체 열 조건부 서식을 복원하고 XLSX 패키지를 검사한다.
5. 저장한 결과를 Excel에서 다시 열어 시트·Table·열·행 수·합계·날짜 체계와 모든 데이터 블록을 원본 지문에 대조한다.
6. 원본과 대상 서명을 다시 확인한 뒤 최종 결과를 게시한다.

값 대조는 논리값·텍스트·숫자·Excel 오류를 구분한다. Excel 저장 시의 숫자 15자리 유효숫자와 빈 문자열의 빈 셀 변환만 정규화한다. 같은 행 수를 가진 잘못된 붙여넣기도 검증 실패로 처리한다. Excel의 시스템 클립보드를 사용하므로 병합 중 다른 프로그램의 복사 작업이 간섭할 수 있으며, 값 불일치가 발견되면 저장 결과를 게시하지 않는다.

동일한 전체 열 조건부 서식이 모든 입력에 있고 수식·적용 범위·스타일·테마·Table 문맥을 입증할 수 있을 때만 원래 전체 열 규칙 하나로 복원한다. 조건이 다르면 Excel이 만든 규칙을 유지한다. UTF-8 워크시트의 셀 데이터는 원래 바이트를 보관해 조건부 서식 검사에서 거대한 셀 DOM을 만들지 않는다. 복원된 집계 수식은 병합된 전체 데이터를 기준으로 평가된다.

## 파일 비교

위치 비교는 같은 시트 이름과 셀 좌표의 계산 값을 비교한다. 양쪽 UsedRange에서 비어 있지 않은 셀의 좌표 합집합을 사용하므로 빈 셀로 바뀐 기존 좌표도 비교한다. 비교대상에만 있는 시트의 값은 모두 추가 셀로 집계하며, 값이 없는 추가 시트는 내역만 표시한다. 기준에만 있는 시트는 누락 시트로 집계하며 셀 차이에 더하지 않는다. 키 비교는 선택한 Table의 열 이름과 하나 이상의 키 열을 사용하므로 행·열 순서가 달라도 대응시킬 수 있다. 중복 키는 임의로 한 행을 선택하지 않고 오류로 처리한다.

비교 대상 파일의 복사본에서 값이 다른 셀을 노란색으로 표시한다. 위치 비교는 값이 지워진 기존 좌표에도 표시한다. 키 비교의 추가 행은 전체를 표시하며, 비교 대상에 아예 없는 시트·행·열은 새로 만들거나 색칠하지 않고 결과 내역에서 알린다. 수식 문자열이 달라도 계산 결과가 같으면 값 변경으로 보지 않으며 논리값·텍스트·숫자·Excel 오류는 구분한다. 키 비교 요약은 공통 행의 변경 셀 수와 추가·누락 행 수를 구분하고, 위치 비교는 차이 셀 수를 센다. 비교 대상의 기존 수식·서식과 관련 없는 시트는 유지한다.

각 원본을 연 뒤 Excel.Calculate로 다시 계산하고 값을 읽으며 외부 링크는 갱신하지 않는다. 셀 값은 최대 32,768셀 단위로 읽는다. 비교 스냅샷은 메모리에 보관하므로 큰 통합문서는 사용 가능한 메모리의 영향을 받는다.

## 시트 정리

선택한 시트에만 도형·메모·댓글 삭제, 직접 채우기 색 초기화, 조건부 서식 삭제를 독립적으로 적용한다. 채우기 초기화는 기본적으로 Table 머리글을 제외하며 제외 설정을 해제할 수 있다. Table 줄무늬·스타일과 조건부 서식에 의한 색은 직접 채우기 색과 별개다. 수식·값·글꼴·테두리·숫자 형식과 다른 시트를 유지하며 빈 영역의 직접 채우기도 처리한다.

## 검증 전략

주요 동작은 실제 Excel로 합성 통합문서를 만들고 서비스를 실행한 뒤 결과를 다시 열어 확인한다. `tests/e2e/test_excel_workflows.py`는 `EXCEL_E2E=1`일 때 다섯 E2E 스크립트를 별도 Python 프로세스로 순차 실행한다. 클립보드를 공유하므로 이 스위트를 병렬 실행하지 않는다.

| 스크립트 | 검증 대상 |
| --- | --- |
| `check_merge_excel.py` | 세션 반복, 값·타입·오류·수식·서식·합계·필터·빈 Table·날짜 체계·조건부 서식·실패 복구·대량 데이터 |
| `check_split_merge_excel.py` | 분할→병합 데이터 보존, 활성 필터, 빈 분류, 중복, 덮어쓰기, 파일 잠금, 오래된 사전 검사, 원본 해시와 임시 파일 |
| `check_compare_excel.py` | 위치·복합 키 비교, 순서 변경, 누락, 색칠, 타입, 수식·서식과 원본 보존 |
| `check_etc_excel.py` | 정리 옵션 조합, 여러 Table 머리글, 도형·댓글, 채우기·조건부 서식과 다른 시트 보존 |
| `check_gui_excel.py` | 실제 Tk 시작 버튼부터 Excel 저장까지, 검사 실패·재시도, 실행 중 잠금, 결과의 비교 화면 연결 |

Tk 화면 테스트는 입력·순서 변경에 따른 사전 검사 무효화, 실행 중 상태, 오류 복구와 결과 동작을 확인한다. 빠른 테스트는 파일 경합, 손상된 복사본, COM 실패, 스레드 종료 등 실제 Excel에서 일정하게 재현하기 어려운 안전 경계를 유지한다. 생성자·상수·전달 호출만 반복 확인하는 테스트는 추가하지 않는다.

`benchmark_merge_cf.py`는 조건부 서식 검사만 측정한다. 전체 병합 시간은 native 대량 데이터 사례의 사전 검사·검증 포함 실행 시간으로 별도 기록한다. 측정 환경에 민감한 시간 제한을 성능 통과 기준으로 사용하지 않는다. 패키징 후에는 EXE의 pywin32 로딩·시작·실제 창 아이콘을 확인한다. 합성 데이터의 통과를 특정 DRM 제품이나 모든 조직별 Excel 구성의 검증으로 확대하지 않는다.
