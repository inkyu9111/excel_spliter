# Excel File Toolkit

`.xlsx` 파일을 **분할 (Split)**하거나 여러 분할 파일을 **병합 (Merge)**하는 Windows GUI 프로그램입니다. 실행 후 탭에서 기능을 선택합니다. GitHub 저장소 이름은 기존 `excel_spliter`를 유지합니다.

- **Split**: 정식 Excel Table(Excel의 **삽입 > 표**) 한 컬럼을 기준으로 나눕니다. 각 결과 파일에는 선택한 워크시트와 해당 분류 값의 행만 남습니다. 빈 셀도 하나의 분류로 처리합니다. 기존 Split 처리 로직을 그대로 사용합니다.
- **Merge**: 열 이름과 순서가 같은 Table의 데이터 행을 파일 목록 순서대로 이어 붙입니다. 머리글은 한 번만 남기고, Table 수식은 각 파일의 현재 계산값으로 합칩니다.

## 실행 환경

- 64비트 Windows 10 또는 Windows 11
- 데스크톱 Microsoft Excel 2016 이상
- 입력·출력 형식: `.xlsx`

DRM 원본은 Excel을 통해서만 열며, Excel이 복호화해야 하므로 데스크톱 Excel이 반드시 필요합니다. 사용자가 같은 PC의 Excel에서 정상적으로 열 수 있는 파일만 처리할 수 있으며, 프로그램은 DRM 원본을 저장하거나 수정하지 않습니다. 결과 파일은 DRM 보호를 유지하지 않습니다.

## Split 처리 원리

1. 프로그램 전용 Excel 인스턴스가 DRM 원본을 읽기 전용으로 한 번 열어 유지합니다.
2. 선택한 워크시트의 정식 Table과 분류 컬럼을 확인하고, 컬럼 값을 한 번에 읽어 분류별 행 수를 계산합니다.
3. 실행 직전에 Excel `SaveAs`로 비보호 임시 원본을 만들고 구조를 검증합니다. 검사와 삭제 대상은 결과에 남는 선택 워크시트뿐입니다. 해당 시트에 제거 대상이 있으면 확인 창에 정확히 `메모 및 도형은 삭제됩니다`를 추가하고, 승인 후 모든 legacy note, threaded comment, 그림, 차트, 버튼, 컨트롤과 그 밖의 `Shapes` 항목을 삭제합니다.
4. 분류 수에 따라 최대 세 개의 독립 Excel 작업자가 정리된 임시 원본을 복사하여 다른 시트와 해당하지 않는 Table 행을 제거합니다. 각 작업자는 별도 Excel 인스턴스를 사용하지만 계산과 저장은 공유 잠금으로 직렬 처리합니다.

원본 파일은 수정하지 않습니다. 선택한 출력 폴더 아래에 DRM 보호가 없는 평문 `.e...` 실행 임시 폴더를 만들며, 정상 완료와 프로그램이 처리한 오류 경로에서는 삭제합니다. 프로세스 강제 종료나 전원 차단 시 남을 수 있으므로, 이 경우 Excel을 종료한 뒤 해당 폴더를 직접 삭제해야 합니다.

## Split 사용 방법

1. 빌드한 `dist/ExcelFileToolkit.exe`를 실행하고 **분할 (Split)** 탭을 선택합니다.
2. **원본 파일** 옆 **찾아보기**에서 `.xlsx` 파일을 고릅니다.
3. 워크시트를 선택합니다. 선택한 시트에는 정식 Excel Table이 정확히 하나 있어야 합니다.
4. 분류할 컬럼을 선택합니다.
5. 파일명 패턴과 출력 폴더를 지정하고 **미리보기**를 누릅니다.
6. 분류 값, 행 수, 결과 파일명을 확인한 뒤 **분할**을 누릅니다.
7. 기존 파일이 있으면 덮어쓸 파일 목록을 확인하고 승인합니다.

### 파일명 패턴

`%`는 분류 값으로 바뀌는 자리표시자입니다.

| 패턴 | 컬럼 값 | 결과 파일명 |
|---|---|---|
| `%_분할` | `서울` | `서울_분할.xlsx` |
| `%_분할` | 빈 셀 | `_분할.xlsx` |

패턴에는 `%`가 하나 이상 필요하며 모든 `%`가 같은 분류 값으로 바뀝니다. `.xlsx`는 자동으로 붙습니다. Windows 파일명에 사용할 수 없는 문자는 `_`로 바뀌며, 이름이 겹치면 ` (2)`, ` (3)`이 붙습니다. 미리보기에 최종 파일명이 표시됩니다.

## Merge 사용 방법

1. **병합 (Merge)** 탭에서 **파일 추가**를 눌러 `.xlsx` 파일을 두 개 이상 선택합니다. 여러 번 추가할 수 있습니다.
2. **위로**, **아래로**, **선택 제거**로 병합할 목록을 정리합니다. 파일 내부의 행 순서는 그대로 유지됩니다.
3. **결과 파일 > 찾아보기**에서 저장할 `.xlsx` 파일을 지정합니다. 기본값은 첫 파일 폴더의 `merged.xlsx`입니다.
4. **미리보기**를 눌러 파일별 워크시트와 데이터 행 수, 전체 행 수를 확인합니다.
5. **병합**을 누르고 결과 경로 및 기존 파일 덮어쓰기 여부를 확인합니다.

각 입력 파일에는 워크시트 하나와 정식 Excel Table 하나가 있어야 하며, 모든 Table의 열 이름과 순서가 정확히 같아야 합니다. Split으로 만든 파일을 그대로 사용할 수 있습니다. 빈 Table은 데이터 0행으로 처리하며 중복 데이터 행은 제거하지 않습니다.

첫 파일의 시트 레이아웃과 Table 스타일을 기준으로 데이터 영역을 확장합니다. Table 머리글은 한 번만 유지하고, 합계 행은 첫 파일의 설정을 사용합니다. 데이터 셀의 값과 셀 서식을 복사하며 **Table 수식 자체는 보존하지 않습니다**. 다른 파일의 Table 밖 콘텐츠는 병합하지 않습니다. 원본 분할 이전의 행 순서를 복원하는 기능은 아닙니다.

입력 파일은 저장하거나 수정하지 않습니다. 결과 경로가 입력 파일과 같으면 거부합니다. 미리보기 이후 입력 파일이나 기존 결과 파일이 변경되면 다시 미리보기를 해야 합니다. 임시 결과의 저장이 완료된 뒤 결과 파일로 게시하며, 실패 시 입력 파일과 기존 결과 파일을 보호합니다.

## Split 제한사항

- 선택한 시트에 정식 Excel Table이 없거나 두 개 이상이면 처리하지 않습니다.
- 외부 데이터에 연결된 Table, 보호되어 행을 삭제할 수 없는 Table, Table 아래에 독립 콘텐츠가 있는 시트는 지원하지 않습니다.
- 결과에서 다른 시트를 삭제하므로 다른 시트를 참조하는 수식, 이름, 차트, 유효성 검사 또는 연결이 손상될 수 있습니다.
- 결과 파일에는 선택한 시트만 유지되며 DRM 보호는 적용되지 않습니다. 그 선택 시트의 모든 legacy note, threaded comment, 그림, 차트, 버튼, 컨트롤과 그 밖의 `Shapes` 항목은 모든 결과에서 삭제됩니다. 다른 시트는 삭제 대상 검사 없이 결과에서 제거됩니다.
- 분할 중에는 작업을 취소하거나 창을 닫을 수 없습니다.
- 일부 파일 처리에 실패해도 이미 성공한 결과는 유지됩니다. 완료 창에서 성공·실패 목록을 확인할 수 있습니다.

## Merge 제한사항

- `.xlsx`만 지원하며, 여러 시트·여러 Table 또는 서로 다른 열 구조의 파일은 병합하지 않습니다.
- 보호된 시트와 외부 데이터 연결 Table은 지원하지 않습니다. 첫 파일의 Table이 확장될 영역에 값·수식·메모·하이퍼링크·병합 셀이 있으면 덮어쓰지 않고 거부합니다. 빈 셀에 남은 서식은 허용하며, 확장 영역 밖의 콘텐츠는 유지합니다.
- 병합 결과가 Excel의 시트 행 수 한도를 넘으면 실행하지 않습니다.
- 다른 파일의 시트 레이아웃, Table 밖 수식·도형·인쇄 설정은 병합 대상이 아닙니다. 첫 파일의 Table 밖 수식과 외부 참조를 복구하거나 정리하지 않습니다.
- 병합 중에는 입력을 바꾸거나 탭을 전환하거나 창을 닫을 수 없습니다.
- 출력 폴더의 `.em-*.xlsx` 임시 결과는 정상 완료와 처리된 오류 시 삭제합니다. 강제 종료 시 남은 임시 파일은 Excel을 종료한 뒤 직접 삭제해야 합니다.

오류 로그는 `%LOCALAPPDATA%\ExcelFileToolkit\logs\excel-file-toolkit.log`에 기록됩니다.

기존 Split의 보존 범위와 오류 처리 계약은 [Split 설계 문서](docs/superpowers/specs/2026-09-01-excel-splitter-design.md)를 참고하세요.

## 소스 실행과 빌드

Python 3.12 환경에서 다음 명령을 실행합니다.

```powershell
python -m pip install -e ".[dev]"
python -m pytest tests/unit -q
python -m excel_splitter
```

설치 후 `excel-file-toolkit` 명령으로도 실행할 수 있습니다. 기존 `excel-splitter` 명령과 `excel_splitter` Python 패키지 경로는 호환성을 위해 유지합니다. 개발·빌드 의존성은 `pyproject.toml`의 `dev` 항목에서 관리합니다.

단일 EXE는 다음 명령으로 빌드합니다. 빌드 스크립트는 고정된 의존성 버전, 단위 테스트, PyInstaller 패키징과 pywin32 로딩을 검증합니다.

```powershell
.\scripts\build.ps1 -PythonExe C:\path\to\python.exe
```

완성 파일은 `dist\ExcelFileToolkit.exe`에 생성됩니다.

데스크톱 Excel이 설치된 PC에서는 다음 명령으로 실제 파일 병합을 추가 검증할 수 있습니다. 임시 샘플을 만들고 병합 값·순서·중복 행·서식·합계·입력 파일 보존을 확인한 뒤 삭제합니다.

```powershell
python scripts/check_merge_excel.py
```

단위 테스트와 EXE의 pywin32 로딩 검사는 실제 Excel 병합 검증을 대신하지 않습니다.
